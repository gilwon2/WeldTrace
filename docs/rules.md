# 검증·판정 규칙

FactoryLens와 같은 원칙을 따릅니다. **파일 전체를 거부할 문제**, **행을 제외할 문제**, **적재하되 기록할 문제**,
그리고 **데이터 오류가 아니라 설비 이상인 것**을 구분합니다.

## 수집·검증 (데이터 문제)

| 코드 | 단계 | 조건 | 처리 | 근거 |
|---|---|---|---|---|
| F1 | 파일 | 필수 컬럼 누락, 빈 파일 | 파일 거부, 실패 배치 기록 | 열 매핑이 틀리면 모든 값이 틀림 |
| P1 | 행 | 열 개수가 헤더와 다름 | 행 제외 (Error) | 쉼표 밀림 |
| P2 | 행 | 필수값 공백 | 행 제외 (Error) | 통신 오류 |
| P3 | 행 | 숫자·날짜 형식 오류 | 행 제외 (Error) | |
| D1 | 행 | 모든 값이 같은 행이 반복 | 첫 행만 적재 (Warning) | 수집 재전송 |
| D2 | 행 | 같은 시각인데 값이 다름 | 그 시각 행 모두 제외 (Error) | 어느 값이 맞는지 알 수 없음 |
| R1 | 행 | 스텝 번호가 레시피 범위 밖 | 행 제외 (Error) | |
| R2 | 행 | 실측 출력 < 0 또는 > 2,500W | 행 제외 (Error) | 물리적으로 불가능 |
| T1 | 행 | 직전까지 가장 늦은 시각보다 이름 | 적재하고 기록 (Warning) | 원본에서 6건 (파일 병합 5, 설비 시계 1) |

**멱등성**

| 키 | 범위 | 구현 |
|---|---|---|
| K1 | 파일 | 같은 설비에 같은 SHA-256 파일이 성공 적재되었으면 건너뜀. 성공 배치에만 거는 필터 유니크 인덱스라 실패한 파일은 다시 시도할 수 있음 |
| K2 | 행 | (설비, 용접 시각) 유니크. 겹치는 파일을 넣으면 새 행만 적재 |

## 판정 (설비 이상)

출력 0, 출력 저하, 설정 이탈은 **데이터는 정상인데 설비가 이상한 것**이므로 검증에서 버리지 않고 판정합니다.

| 코드 | 조건 | 결과 |
|---|---|---|
| NO_OUTPUT | 실측 출력 = 0 | 불량 |
| POWER_DROP | 실측 / 스텝 공칭 출력 < 0.95 | 불량 |
| RECIPE_DEVIATION | 설정 출력 ≠ 스텝 지정값 | 경고 |

모듈 판정: 불량 용접이 하나라도 있으면 NG, 경고만 있으면 WARNING, 39스텝이 다 없으면 HOLD.
대표 불량 우선순위: NO_OUTPUT > POWER_DROP > RECIPE_DEVIATION.

## 모듈 조립

- 도착 순서(weld_id)로 묶습니다. 시각 순서로 정렬하면 T1(시간 역전) 행이 다른 모듈로 섞입니다.
- 새 모듈 시작: 스텝 번호가 직전 이하로 돌아감, 또는 직전 용접과 30분 넘게 떨어짐.
- 파일 끝에서 잘린 모듈은 **열어 둡니다**. 다음 파일이 이어지면 합쳐서 닫고, 새 모듈이 시작되면 HOLD로 닫습니다.
